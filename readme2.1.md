# LAB Switch (ต่อ) : ส่ง Traffic พร้อมกัน, Collision Domain vs Broadcast Domain

ทดลองให้ **สองเครื่องส่ง traffic พร้อมกันผ่าน Switch** เพื่อเทียบกับ Hub ที่เคยเกิด Collision

การทดลองต้องการพิสูจน์ **สองเรื่องแยกกัน**:

1. Switch แยกการเชื่อมต่อแต่ละพอร์ต ทำให้การส่งจากคนละพอร์ต **ไม่ชนกัน** แบบสื่อกลางร่วมของ Hub
2. Switch ยัง **ส่งต่อ Broadcast** ไปถึงเครื่องอื่นในวงเดียวกัน แม้จะแยก Collision Domain แล้ว

**ดังนั้น Network ในตัวอย่างนี้มี 4 Collision Domains แต่มี 1 Broadcast Domain**

---

## 1. เตรียมให้ PC5 และ PC6 รู้ MAC ของ PC8 ก่อน

ใช้ภาพเดิม โดยกำหนดหมายเลขพอร์ตเพื่ออธิบาย:

```text
PC5 ── พอร์ต 1 ──┐
PC6 ── พอร์ต 2 ──┤
                 [ Switch ]
PC7 ── พอร์ต 3 ──┤
PC8 ── พอร์ต 4 ──┘
```

ให้ PC6 ping PC8 แบบ Real-Time ก่อน เพื่อให้ ARP ทำงานจน PC6 รู้ MAC ของ PC8 ส่วน PC5 รู้แล้ว

```text
ARP Cache ของ PC5: IP ของ PC8 → MAC ของ PC8
ARP Cache ของ PC6: IP ของ PC8 → MAC ของ PC8
```

**ทำไมต้องเตรียมแบบนี้?**
เพราะครั้งนี้ต้องการดูว่า ถ้าทั้งสองเครื่องส่ง ICMP ได้ทันที จะเกิด Collision หรือไม่ จึงจัดให้ไม่ต้องเริ่มด้วย ARP Request หา PC8 อีก

**อย่าสับสนกับตารางของ Switch:**

- PC เก็บ **IP → MAC**
- Switch เรียนรู้ **MAC → พอร์ต** จาก traffic ที่ผ่านเข้ามา

## 2. PC5 และ PC6 ping PC8 พร้อมกัน

```text
PC5 ── ICMP ── พอร์ต 1 ──┐
                         [ Switch ] ── พอร์ต 4 ──▶ PC8
PC6 ── ICMP ── พอร์ต 2 ──┘
```

ทั้งสองส่งเข้า **คนละพอร์ต** ของ Switch จึงไม่ได้ใช้ทางส่งร่วมกันแบบ Hub

**แต่ทั้งคู่ต้องออกพอร์ต 4 ไป PC8 เหมือนกัน แล้วทำอย่างไร?**
Switch ส่ง Frame แรกไปก่อน แล้วส่งอีก Frame ตามไป โดยพักข้อมูลที่ต้องรอไว้ใน **Buffer** (พื้นที่เก็บข้อมูลชั่วคราว)

```text
Frame จาก PC5 ──┐
                ├──▶ [ รอส่งออกพอร์ต 4 ] ──▶ PC8
Frame จาก PC6 ──┘            │
                             └─ ส่งทีละ Frame
```

คำว่า "caches the packet" ในวิดีโอ ให้เข้าใจว่า **พักข้อมูลไว้รอส่ง** ไม่ใช่เอา packet ไปเก็บใน ARP Cache หรือ MAC Address Table

สอง Frame ใช้พอร์ตออกเดียวกัน จึงรอส่งตามลำดับ แต่ **ไม่ได้ชนกันแบบ Hub**

## 3. เปลี่ยนเป็นสองคู่สนทนา

```text
คู่ที่ 1: PC5 ping PC8
คู่ที่ 2: PC6 ping PC7
```

ตอนแรก PC6 ยังไม่รู้ MAC ของ PC7 จึงต้องส่ง **ARP Request** ก่อน
การรู้ MAC ของ PC8 ไม่ได้ทำให้รู้ MAC ของ PC7 เพราะเป็นข้อมูลคนละรายการ:

```text
ARP Cache ของ PC6 หลังเรียนรู้แล้ว
  IP ของ PC7 → MAC ของ PC7
  IP ของ PC8 → MAC ของ PC8
```

แม้มี ARP ในการทดลองนี้ ก็ **ไม่เกิด Collision** แบบที่เคยเห็นกับ Hub
ย้ำ Concept เดิมว่า **การเป็น Broadcast ไม่ใช่สาเหตุที่ทำให้ต้องเกิด Collision**

## 4. ทดลองซ้ำเมื่อทั้งสองคู่พร้อมส่ง ICMP

เมื่อเรียนรู้ MAC แล้ว ทั้งคู่ส่ง Unicast:

```text
PC5 ── พอร์ต 1 ──▶ [ Switch ] ── พอร์ต 4 ──▶ PC8
PC6 ── พอร์ต 2 ──▶ [ Switch ] ── พอร์ต 3 ──▶ PC7
```

ครั้งนี้ใช้พอร์ตเข้าและพอร์ตออก **คนละชุดกัน**:

| คู่สนทนา  | พอร์ตที่ใช้   |
| --------- | ------------- |
| PC5 ↔ PC8 | พอร์ต 1 และ 4 |
| PC6 ↔ PC7 | พอร์ต 2 และ 3 |

จึงสื่อสารได้โดยไม่ต้องแย่งสื่อกลางเดียวกันทั้งวงเหมือน Hub

**ระวังความหมาย:** คำว่า "แยกจากอีกการสนทนา" ในช่วงนี้หมายถึง Unicast ของแต่ละคู่ถูกส่งไปยังพอร์ตที่เกี่ยวข้อง **ไม่ได้หมายความว่าอยู่คนละ Broadcast Domain**

## 5. Switch แยก Collision Domain แต่ Broadcast ยังไปถึงทุกเครื่อง

ถ้า PC5 ส่ง Broadcast:

```text
PC5 ── Broadcast ──▶ Switch
                       ├── พอร์ต 2 ──▶ PC6
                       ├── พอร์ต 3 ──▶ PC7
                       └── พอร์ต 4 ──▶ PC8
```

Broadcast ถูกส่งออกพอร์ตอื่น **ยกเว้นพอร์ตขาเข้า** ดังนั้นแม้ Unicast ส่งแยกตามพอร์ตได้ แต่ Broadcast ยังแพร่ถึง PC อื่นทั้งหมดในวงนี้

**จุดที่ต้องปรับให้แม่น:** ในวิดีโอพูดว่าทุกเครื่องต้องตอบ Broadcast แต่จริง ๆ **ได้รับ Broadcast ไม่ได้แปลว่าต้องตอบทุกเครื่อง**

```text
ARP Request ถามหา IP ของ PC8
        │
        ├── PC6 ได้รับ → ไม่ใช่ IP ของตน → ไม่ตอบ
        ├── PC7 ได้รับ → ไม่ใช่ IP ของตน → ไม่ตอบ
        └── PC8 ได้รับ → เป็น IP ของตน   → ตอบ
```

การตอบขึ้นกับชนิดข้อความและเงื่อนไขของผู้รับ ส่วนหลักฐานของ Broadcast Domain คือ **Broadcast แพร่ไปถึงไหน**

## นับ Domains: ชี้ขอบเขตทีละส่วน

### Collision Domains: 4 วง

แต่ละการเชื่อมต่อกับพอร์ต Switch แยกเป็นหนึ่ง Collision Domain

```text
[ PC5 ── พอร์ต 1 ]   ← Domain 1
[ PC6 ── พอร์ต 2 ]   ← Domain 2
[ PC7 ── พอร์ต 3 ]   ← Domain 3
[ PC8 ── พอร์ต 4 ]   ← Domain 4
            │
         [Switch]
```

1. PC5 ↔ พอร์ต 1
2. PC6 ↔ พอร์ต 2
3. PC7 ↔ พอร์ต 3
4. PC8 ↔ พอร์ต 4

รวม **4 Collision Domains**

- **ไม่ได้นับตามจำนวนคู่สนทนา** แม้คุยกันสองคู่ ก็ยังมีสี่การเชื่อมต่อแยกกันที่พอร์ต Switch
- Collision Domain บอก **ขอบเขตของการเชื่อมต่อ** ไม่ได้หมายความว่าทุกวงต้องเกิด Collision ให้เห็นในการทดลอง

### Broadcast Domain: 1 วง

คำถามคราวนี้คือ: **Broadcast จาก PC5 ไปถึงใครบ้าง?**
มันผ่าน Switch ไปถึง PC6, PC7 และ PC8 จึงครอบทั้งหมดเป็นขอบเขตเดียว

```text
┌────────────── 1 Broadcast Domain ──────────────┐
│                                                │
│ PC5 ── พอร์ต 1 ──┐                             │
│ PC6 ── พอร์ต 2 ──┤                             │
│                  [ Switch ]                    │
│ PC7 ── พอร์ต 3 ──┤                             │
│ PC8 ── พอร์ต 4 ──┘                             │
│                                                │
└────────────────────────────────────────────────┘
```

> หมายเหตุเพิ่มเติม: นับเป็น 1 Broadcast Domain เพราะ Switch ตัวนี้ใช้ VLAN เดียวตามค่าเริ่มต้น ถ้าแบ่ง VLAN จะได้หลาย Broadcast Domain (ยังไม่ต้องสนใจในแล็บนี้)

### เปรียบเทียบ Hub กับ Switch

| เครือข่าย                               | Broadcast Domains                  | Collision Domains                |
| --------------------------------------- | ---------------------------------- | -------------------------------- |
| PC 4 เครื่องผ่าน **Hub**                | 1 (Broadcast ถึงทุกเครื่องในวง)    | 1 (ทุกเครื่องใช้สื่อกลางร่วมกัน) |
| PC 4 เครื่องผ่าน **Switch** ตามตัวอย่าง | 1 (Broadcast ยังถึงทุกเครื่องในวง) | 4 (แยกตามสี่พอร์ตที่เชื่อมต่อ)   |

## จดลง Notebook (สำหรับ CCNA)

- Hub ในตัวอย่าง: **1 Broadcast Domain / 1 Collision Domain**
- Switch ในตัวอย่าง: **1 Broadcast Domain / 4 Collision Domains**
- Switch แยก Collision Domain ตามแต่ละพอร์ตที่เชื่อมต่อ
- Unicast ที่รู้พอร์ตปลายทางแล้ว ถูกส่งเฉพาะพอร์ตนั้น
- ถ้าหลาย Frame ต้องออกพอร์ตเดียวกัน Switch พักใน **Buffer** แล้วส่งตามลำดับ
- Broadcast ยังถูกส่งออกพอร์ตอื่นในวงเดียวกัน
- ได้รับ Broadcast ≠ ต้องตอบ Broadcast

## Concept ที่ต้องเข้าใจ

เวลาเห็นภาพเครือข่าย ให้ถามสองคำถามนี้:

- **Broadcast Domain:** ถ้าเครื่องนี้ส่ง Broadcast มันแพร่ไปถึงส่วนไหนบ้าง?
- **Collision Domain:** ส่วนไหนใช้สื่อกลางร่วมกัน และส่วนไหนถูก Switch แยกออกจากกัน?

ในภาพ Switch นี้ มี **Broadcast Domain ใหญ่หนึ่งวง** ครอบการเชื่อมต่อที่แยกเป็น **Collision Domains สี่วง** อยู่ภายใน

ส่วน **Subnet** เป็นเรื่องของ IP กับ Subnet Mask ไม่ต้องนำจำนวน Subnet มาแทนจำนวน Domains ในการทดลองนี้
