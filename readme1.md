# LAB CCNA: วิเคราะห์ทราฟฟิกผ่าน Hub (ARP & ICMP)

เครือข่ายจำลองประกอบด้วย PC 4 เครื่อง เชื่อมต่ออยู่บน **Hub ตัวเดียวกัน** (อยู่ในวง LAN เดียวกัน):

- `PC1` (เครื่องต้นทางที่ต้องการทดสอบ)
- `PC2` และ `PC3` (เครื่องรอบข้างที่ไม่ได้ร่วมสนทนา แต่ต่ออยู่กับ Hub)
- `PC4` (เครื่องปลายทางที่ถูก ping)

---

## 3 Concept สำคัญที่ต้องฝังหัว (Core Concepts)

1. **สั่ง `ping` ไม่ได้แปลว่าสิ่งแรกที่ออกมาต้องเป็น ICMP เสมอไป**
   - ในเงื่อนไขเริ่มต้น (ตาราง ARP Cache ว่าง) ก่อนที่ PC1 จะส่ง ICMP ของการ ping ได้ PC1 **ต้องตามหา MAC Address ของ PC4 ด้วย ARP ก่อนเสมอ**
2. **“ได้รับ” (Received) ไม่เท่ากับ “เป็นผู้รับที่ข้อมูลส่งถึง” (Intended Recipient)**
   - แม้ Hub จะส่งสัญญาณไปถึงทุกเครื่อง แต่ตัวการ์ดแลน (NIC) ของ PC2 และ PC3 จะเปิดดู Ethernet Header แล้วพบว่าไม่ใช่ MAC ของตน จึงทำการ **ทิ้ง (Drop/Discard) แพ็กเกจนั้นทิ้งทันที** มีเพียงเครื่องปลายทางที่ถูกต้องเท่านั้นที่รับไว้
3. **Broadcast กับการส่งต่อของ Hub เป็นคนละเรื่องกัน**
   - **Broadcast** คือ "ลักษณะคำสั่งในระดับ Logical/Data Link" ที่ระบุว่าส่งหาทุกคน
   - **พฤติกรรมของ Hub** คือ "ลักษณะทางกายภาพที่ Layer 1" ที่ทำการ Copy สัญญาณออกทุกพอร์ต (Blind Forwarding) เสมอ **แม้ว่า Frame นั้นจะเป็นการส่งแบบ Unicast (เจาะจงคนเดียว) ก็ตาม**

## ลำดับเหตุการณ์จำลอง (Simulation Event List Timeline)

เมื่อเราเปิดโหมด Simulation และตั้งค่า Filter ให้แสดงเฉพาะ **ARP + ICMP** จะพบการทำงานเรียงตามลำดับดังนี้:

### ลำดับที่ 1: ก่อนส่ง Ping — PC1 ตามหา MAC ด้วย ARP Request

- **สิ่งที่ส่ง:** ARP Request
- **ผู้ส่ง:** PC1
- **MAC ปลายทาง:** Broadcast (`FF:FF:FF:FF:FF:FF`)
- **เส้นทางผ่าน Hub:** Hub รับจาก PC1 แล้วกระจายออกทุกพอร์ต ทำให้ **PC2, PC3 และ PC4 ได้รับ**
- **การประมวลผล:**
  - PC2 และ PC3 ได้รับ แต่ตรวจสอบคำถามข้างในแล้วพบว่า _IP ที่ถามไม่ใช่ของตน_ จึงทิ้งแพ็กเกจ
  - **PC4** ได้รับ และตรวจสอบพบว่า _IP ที่ถามเป็นของตน_ จึงเตรียมสร้าง ARP Reply ตอบกลับ

### ลำดับที่ 2: ขากลับของ ARP — PC4 ตอบกลับด้วย ARP Reply

- **สิ่งที่ส่ง:** ARP Reply
- **ผู้ส่ง:** PC4
- **MAC ปลายทาง:** เป็น **Unicast** ระบุเจาะจงส่งกลับไปหา **MAC ของ PC1**
- **เส้นทางผ่าน Hub:** แม้ใน Frame จะระบุผู้รับแค่ PC1 แต่ด้วยข้อจำกัดของ Hub ที่ทำงานที่ Layer 1 มันจึง **ส่งสัญญาณออกไปยังทุกพอร์ตเช่นเดิม** ทำให้ PC1, PC2 และ PC3 ได้รับสัญญาณนี้
- **การประมวลผล:**
  - **PC1** ตรวจสอบพบว่า MAC ปลายทางตรงกับตน จึง **รับไว้**
  - PC2 และ PC3 ได้รับเช่นกัน แต่ตรวจสอบแล้ว MAC ปลายทางไม่ใช่ของตน จึง **ทิ้ง**

### ลำดับที่ 3: เริ่มส่ง Ping — PC1 ส่ง ICMP Echo Request

- เมื่อ PC1 ได้รับ MAC ของ PC4 แล้ว จึงห่อหุ้มใน Ethernet Frame (MAC ปลายทาง = PC4, IP ปลายทาง = IP ของ PC4) แล้วส่งข้อความสำหรับ ping
- **สิ่งที่ส่ง:** ICMP Echo Request (ขอเช็คสัญญาณเชื่อมต่อ)
- **ผู้ส่ง:** PC1
- **MAC ปลายทาง:** MAC ของ PC4 (Unicast)
- **เส้นทางผ่าน Hub:** Hub ส่งต่อไปทุกพอร์ต (**PC2, PC3, PC4 ได้รับหมด**)
- **การประมวลผล:**
  - PC2 และ PC3 ได้รับ แต่ไม่ใช่ผู้รับที่แท้จริง จึงทิ้ง
  - **PC4** เป็นผู้รับที่ถูกต้อง จึงทำการประมวลผลและเตรียมตอบกลับ

### ลำดับที่ 4: ขากลับของ Ping — PC4 ส่ง ICMP Echo Reply

- **สิ่งที่ส่ง:** ICMP Echo Reply (ตอบกลับว่าเชื่อมต่อปกติ)
- **ผู้ส่ง:** PC4
- **MAC ปลายทาง:** MAC ของ PC1 (Unicast)
- **เส้นทางผ่าน Hub:** Hub ส่งต่อออกทุกพอร์ต (**PC1, PC2, PC3 ได้รับ**)
- **การประมวลผล:**
  - **PC1** ตรวจสอบ MAC ตรงกับตน จึงรับไว้ (หน้าจอ Command Prompt ขึ้นคำว่า `Reply from...`)
  - PC2 และ PC3 ทิ้งแพ็กเกจเพราะไม่ใช่ของตน

## เครื่องมือวิเคราะห์และคำสั่งที่ต้องรู้

- **Event List:** ตารางบันทึกเหตุการณ์ทีละสเต็ป ดูว่าทราฟฟิกวิ่งผ่านอุปกรณ์ไหนและกำลังทำอะไรอยู่
- **OSI Model Tab:** ตรวจสอบว่าในแต่ละสเต็ป อุปกรณ์กำลังประมวลผลข้อมูลอยู่ที่ Layer ใด
- **Inbound / Outbound PDU Details:** ใช้ตรวจดูไส้ในของแพ็กเกจ เช่น MAC ต้นทาง/ปลายทาง, IP ต้นทาง/ปลายทาง
- **คำสั่ง `ipconfig /all` (บน PC):** ใช้ตรวจสอบ MAC Address จริงของเครื่อง เพื่อนำไปเทียบเคียง (Proof) กับค่าใน PDU Details ยืนยันว่าแพ็กเกจส่งถึงเครื่องจริง ๆ
- **Filter (ARP + ICMP):** ตัวกรองหน้าจอจำลองให้แสดงเฉพาะทราฟฟิกของการหา MAC และการ ping

## สรุปสิ่งที่ควรจดลง Notebook สำหรับเตรียมสอบ CCNA

- **ARP Request:** ใช้ถามหา MAC Address ของเครื่องที่มี IP เป้าหมาย (ส่งแบบ **Broadcast**)
- **ARP Reply:** ส่งข้อมูล MAC Address กลับไปยังเครื่องถาม (เป็นแบบ **Unicast**)
- **Ping:** ใช้โปรโตคอล **ICMP** ประกอบด้วย _Echo Request_ และ _Echo Reply_
- **พฤติกรรม Hub:** ทำงานที่ **Layer 1 (Physical)** รับสัญญาณเข้ามาแล้ว Copy ออกทุกพอร์ตทันที ทำให้เครื่องรอบข้างได้รับทราฟฟิกทั้งหมด
- **โครงสร้างการห่อหุ้มข้อมูล (Encapsulation):**
  - **ICMP** ถูกห่อหุ้มอยู่ภายใน **IPv4 Packet** อีกที
  - **ARP Message** ถูกบรรจุอยู่ภายใน **Ethernet Frame** โดยตรง (ไม่ได้อยู่ภายใน IPv4 Packet)
- **คำสั่งตรวจสอบระบบ:**
  - `show ip eigrp neighbors` (เช็คเพื่อนบ้าน EIGRP)
  - `show ip route` (เช็คตารางเส้นทาง)
  - `ping` / `tracert` (ทดสอบการสื่อสารและเช็คเส้นทาง)

ให้ PC2 ping PC4 ก่อน เพื่อให้ PC2 เรียนรู้ MAC ของ PC4 และตรวจให้ PC1 รู้ด้วย

arp -a ของ PC เครื่องนั้น

PC1: รู้ MAC ของ PC4 แล้ว
PC2: รู้ MAC ของ PC4 แล้ว
จากนั้นให้ทั้งสองส่ง ping อีกครั้ง คราวนี้ทั้งคู่สามารถส่ง ICMP ไปหา PC4 โดยไม่ต้องเริ่มด้วย ARP Request สำหรับ PC4
PC1 ── ICMP ไป PC4 ──┐
├──▶ Hub → เกิด Collision เมื่อส่งทับกัน
PC2 ── ICMP ไป PC4 ──┘

แม้รู้ MAC ปลายทางแล้ว และส่งแบบ Unicast ก็ยังชนกันได้ เพราะยังใช้สื่อกลางร่วมกัน

ดังนั้น ARP กับ Collision เป็นคนละเรื่อง

- ARP ช่วยหา MAC Address
- Collision เกิดจากการส่งทับกันบนสื่อกลางร่วมกัน

6. ทำไมจึงเป็น Collision Domain เดียว?
   Collision Domain คือขอบเขตที่อุปกรณ์ใช้สื่อกลางร่วมกัน และการส่งของเครื่องหนึ่งสามารถชนกับการส่งของอีกเครื่องในขอบเขตนั้นได้

ในภาพนี้ PC1, PC2, PC3 และ PC4 ต่อผ่าน Hub เดียวกันทั้งหมด ทุกเครื่องจึงอยู่ในวงที่สามารถรบกวนการส่งของกันและกันได้
ไม่ใช่แค่ PC1 กับ PC2 เพราะสองเครื่องนี้ถูกเลือกมาทดลองเท่านั้น PC3 และ PC4 ก็ใช้สื่อกลางเดียวกัน

Domain คำถามที่ใช้หา
Broadcast Domain Broadcast แพร่ไปถึงส่วนใดบ้าง?
Collision Domain ส่วนใดใช้สื่อกลางร่วมกันจนส่งชนกันได้?

Network 1: PC สี่เครื่องต่อผ่าน Hub เดียวกัน

- 1 Broadcast Domain: Broadcast จากเครื่องหนึ่งไปถึงเครื่องอื่นทั้งหมดในวงนี้
- 1 Collision Domain: ทุกเครื่องใช้สื่อกลางร่วมกัน จึงส่งชนกันได้
- Hub ไม่ได้แยก Collision Domain ต่อพอร์ต
- Unicast ก็เกิด Collision ได้ถ้าส่งทับกันบนสื่อกลางร่วมกัน
- การรู้ MAC ใน ARP Cache ไม่ได้ป้องกัน Collision
- ศัพท์ตาม Layer: Bits → Frames → Packets → Segments → Data
  🧠 จำเอาไว้ — Concept ที่ต้องเข้าใจ
  Broadcast Domain ดู “ขอบเขตการแพร่ของ Broadcast” ส่วน Collision Domain ดู “ขอบเขตการใช้ทางส่งร่วมกัน”
  ในเครือข่าย Hub นี้ ทั้งคู่มีขอบเขตครอบ PC ทั้งสี่เหมือนกัน จึงได้จำนวนอย่างละหนึ่ง แต่ไม่ได้แปลว่าสองคำนี้หมายถึงสิ่งเดียวกัน
  ส่วน Subnet ที่คุณเรียนมาเป็นการแบ่งเครือข่ายจาก IP และ Subnet Mask ตอนนี้เราไม่ได้ใช้การคำนวณ Subnet มานับสอง Domains นี้ เรากำลังสังเกตพฤติกรรมการส่งจริงผ่าน Hub ก่อนครับ
